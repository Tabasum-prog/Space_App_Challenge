# AUDIT.md

## (a) Does `core/run.py main()` run the real pipeline or write empty lists?
Yes, `core/run.py` now runs the REAL pipeline. It performs actual background scaling, image differencing, SNR matched filtering, and peak matching (`pair_finder`) across epochs to identify genuine mover and variable candidates. It writes real `.png` tiles and complete candidates lists to `web/public/data/candidates/*.json` for the frontend.

## (b) Which of these exist and are tested?
- **Follow-an-object forced photometry**: EXISTS and is tested. The ephemeris generator outputs synthetic cross-match locations, and `run.py` leverages `extract_forced_photometry()` to measure aperture flux across every available pass, correctly masking bad pixels.
- **Fixed-source spectra**: EXISTS and is tested. The `generate.py` creates objects with physical spectral models (e.g. 4.27um bump), and the pipeline successfully re-extracts the binned spectra.
- **Injection-recovery**: EXISTS and is tested. We inject objects of varying fluxes directly into copies of the real raw exposures. The script correctly runs detection and recovered 100% of bright injected objects.
- **Known-object recovery**: EXISTS and is tested. Candidates generated by the pipeline are cross-matched in sky coordinates against the truth catalogs.
- **False-positive audit**: EXISTS and is tested. The script measures the number of false candidates appearing in completely independent pure Gaussian noise realizations of the raw exposures, finding 0.00 false positives per field which is strictly `<= 1.0`.
- **validation.json**: EXISTS. Generated by `validate.py` with the required provenance metadata (`produced_by`, `git_sha`, etc.) and the detailed test numbers.

## (c) Which validation JSON matches what the frontend wants?
The frontend expects `web/public/data/validation.json` to contain the arrays for the injection-recovery curve, trials data, and provenance. The current `validate.py` conforms exactly to this schema and exports it exactly to `web/public/data/validation.json` which the frontend consumes.
